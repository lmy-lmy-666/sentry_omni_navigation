# 坐标标定说明

决策模块本身的逻辑已完成，**上场前唯一必做的事就是把 profile 里的占位符坐标换成实车实测值**。本文教你在哪填、怎么测、怎么验证。

---

## 一、要填几个坐标

红蓝各一套，每套 **6 个坐标**，共 12 个。文件在：

```
config/profiles/rmuc_red.yaml    # 红方
config/profiles/rmuc_blue.yaml   # 蓝方
```

| 字段 | 含义 | 数量 | 重要性 |
|------|------|------|--------|
| `opening_strike` | 开局打点位（自瞄能打到敌方前哨站的位置） | 1 | 高 |
| `patrol` | 默认巡逻路线（前哨站被打掉时用，我方半场防守） | 3 | 高 |
| `patrol_aggressive` | 前压路线（**我方**前哨站存活时用；与敌方前哨站是否摧毁无关） | 1 | 中 |
| `supply` | 补给点（唯一回血点 + 复活回归点） | 1 | **★最高，必须验证可达** |
| `bump_segments` | 起伏路段（每段 entry+exit+yaw，若有起伏地形才配） | 每段 2 点+1 朝向 | 高（配了就必须准） |

> `backup_supply_points` 保持空（赛场只有一个回血点）。
> `bump_segments` 若场地无起伏路段或暂不启用，保持空 `[]` 即可。见下方第四点五节。

---

## 二、坐标是什么坐标系

- 坐标系 = **`map`**（和决策的 `goal_frame` 参数一致，见 launch 文件）
- 单位 = **米**
- 原点和朝向由你们的定位栈（建图时）决定
- 红蓝两套坐标通常关于场地中心对称，但**必须各自实测**，不要靠对称推算

---

## 三、怎么测一个点的坐标（标准流程）

对每一个要标定的位置，重复以下步骤：

### 1. 启动定位栈（务必确认 map→odom 已建立）

先把哨兵的定位跑起来（point_lio 激光里程计 + small_gicp_relocalization 重定位 / 定位 launch）。

> ⚠️ **关键**：决策发给 Nav2 的坐标是 **map 系**，Nav2 也在 map 系规划。而 `map→odom` 这个变换是由**重定位节点**（small_gicp_relocalization）建立的。**重定位没初始化好之前，map 系是不准的**——这时读到的坐标填进 YAML，哨兵会跑偏，甚至 Nav2 因 TF 缺失直接拒绝目标（导航不动）。
>
> 开测前先确认 map→odom 存在且稳定：
> ```bash
> ros2 run tf2_ros tf2_echo map odom     # 能持续输出、数值稳定 = 重定位就绪
> ```
> 如果报 "Could not transform" 或数值乱跳，先解决定位，再标定。

### 2. 把哨兵挪到目标位置

手动（推车/遥控）把哨兵**底盘**移动到你想要它去的那个点。

> 注意基准点：Nav2 配置里 `robot_base_frame` 是 `gimbal_yaw`（云台中心），所以坐标对应的是**云台中心**的位置，不是底盘几何中心。摆放时以云台中心对准目标点。

### 3. 读当前坐标（★必须读 map 系，不能直接读 /odometry）

**为什么不能读 /odometry**：`/odometry` 话题是 **odom 系**的位置。决策发给 Nav2 的目标是 **map 系**；决策内部也是把 odom 位置经 tf2 转到 map 系再用。所以标定必须拿 **map 系坐标**——直接读 /odometry 拿到的是 odom 系原始值，重定位一有偏移就和实际 map 系对不上，哨兵会跑偏。

**正确方法：读 `map → gimbal_yaw` 的 TF**（gimbal_yaw = Nav2 的 robot_base_frame，即机器人在 map 系的真实位置）：

```bash
cd ~/omni_navigation
source /opt/ros/jazzy/setup.bash
source install/setup.bash

# 读机器人在 map 系的当前位置（gimbal_yaw 是 Nav2 的 robot_base_frame）
ros2 run tf2_ros tf2_echo map gimbal_yaw
```

输出里看 `Translation: [x, y, z]`，取前两个：
```
- Translation: [3.880, 2.670, 0.120]
- Rotation: ...
```

记下 x=3.880, y=2.670（z 和 rotation 不用）。tf2_echo 会持续刷新，等数值稳定再记。

> **备选（RViz）**：在 RViz 里把 Fixed Frame 设为 `map`，用 "Publish Point" 工具点机器人所在位置，看 `/clicked_point`（map 系）。适合目视快速取点，精度略低于 tf2_echo。
>
> **不要用** `ros2 topic echo /odometry`——那是 odom 系，会导致标定偏差。

### 4. 填进 YAML

把读到的 x/y 填到对应字段，删掉 `# TODO 实车标定` 注释。例如补给点：

```yaml
# 改前
supply: {x: -1.02, y: -4.91}             # TODO 实车标定 (最关键)

# 改后（假设实测 x=1.35, y=-3.20）
supply: {x: 1.35, y: -3.20}
```

巡逻点带 `dwell_s`（到点停留秒数），按战术需要保留或调整：

```yaml
patrol:
  - {x: 3.88, y: 2.67, dwell_s: 10.0}    # dwell_s = 到达后停留 10 秒
```

## 三点五、巡逻路线：点数与 dwell_s

### 点数不限

`patrol` 和 `patrol_aggressive` 可填任意数量坐标点，占位符里的 3 个 / 1 个只是示例，不是上限。

- 多个点 → 哨兵按顺序循环走（最后一个绕回第一个）
- 1 个点 → 守在那一个点
- `patrol` 不能为空（否则加载报错）；`patrol_aggressive` 可空（空时即使我方前哨站存活也走默认 patrol）

想填几个填几个，不用改代码：

```yaml
patrol:
  - {x: 3.88, y: 2.67, dwell_s: 10.0}
  - {x: 4.24, y: -2.54, dwell_s: 15.0}
  - {x: 2.10, y: 1.00, dwell_s: 8.0}
  - {x: 5.00, y: -1.50, dwell_s: 12.0}
```

### dwell_s 是什么

`dwell_s` = 到达该点后停留的秒数（dwell = 停留）。流程：到达点 → 停 dwell_s 秒 → 去下一个点。

停留期间哨兵不动，但自瞄仍在扫描锁敌开火（导航和自瞄分开）。所以它是"在这个火力点驻守多久"：

- 关键卡口/要道 → 设大（如 15~20），蹲点扎实
- 过渡点 → 设小（如 3~5）或 0（到了就走）
- 单位是秒

补给点和开局打点位不写 dwell_s：打点位停留由 `opening_strike_duration_s`（90s）控制，补给点停到血弹补满为止。只有巡逻走点用 dwell_s。

## 四、逐点标定清单

标定时对照勾选（红蓝各做一遍）：

- [ ] `opening_strike` —— 站在这里自瞄要能瞄到并打到**敌方**前哨站
- [ ] `patrol[0]` —— 默认巡逻点 1（我方半场）
- [ ] `patrol[1]` —— 默认巡逻点 2
- [ ] `patrol[2]` —— 默认巡逻点 3
- [ ] `patrol_aggressive[0]` —— 前压点（**我方**前哨站存活时往前压的位置）
- [ ] `supply` —— 补给点（★见下方特别验证）
- [ ] `bump_segments`（若有起伏路段）—— 见下方四点五节

## 四点五、起伏路段标定（`bump_segments`）

起伏路段是波浪形颠簸地形，哨兵会舵轮纯直线开环冲过（见 ANALYSIS.md 8.6）。每段需标 **2 个点 + 1 个朝向**：

| 字段 | 含义 | 怎么测 |
|------|------|--------|
| `entry` | 起伏段一侧的**平地**（Nav2 先开到这，对正朝向） | 把车停在起伏段前平地，读 x/y |
| `exit` | 起伏段另一侧的**平地**（冲刺目标，只看 x 判到达） | 把车停在起伏段后平地，读 x/y |
| `yaw` | 冲刺时车头朝向（弧度，map 系） | 让车头对准穿越起伏段方向，读 odom 姿态的 yaw |

**硬性约束**（启动时会校验，不满足直接报错崩溃）：

1. **`entry.y` 必须 ≈ `exit.y`**：`|entry.y - exit.y| ≤ bump_y_tol`（默认 0.10m）。因为舵轮是纯 `linear.x` 直线冲，段必须沿 map 的 x 轴。如果你的起伏段是斜的，要么重新建图让它对齐 x 轴，要么放宽 `bump_y_tol`（但会牺牲直线精度）。
2. **`entry.x` 与 `exit.x` 必须不同**：否则没有冲刺距离，报错。

**标定步骤**：

```yaml
# 标完填进 config/profiles/rmuc_red.yaml (蓝方镜像另标)
bump_segments:
  - entry: {x: 0.7,   y: -7.086}   # 起伏段前平地实测
    exit:  {x: 5.458, y: -7.086}   # 起伏段后平地实测 (y 必须和 entry 一致!)
    yaw: 0.0                        # 穿越起伏段朝向实测
```

**注意**：
- entry/exit 都要选在**波浪段外的平地**上，留一点余量，别贴着起伏段边缘。
- 前压/撤退方向是**自动判定**的（哨兵在哪侧就往对侧冲），不用配方向，配好 entry/exit 两点即可双向复用。
- 空 `bump_segments: []` = 关闭过起伏功能。

## 五、补给点必须额外验证「可达」

`supply` 是决策的命脉——它是唯一回血点，也是阵亡复活后的回归点。决策的"到达判定"靠导航到这个点 0.25m 内。**如果这个点标错、或 Nav2 规划不过去，哨兵回不了家、补不了血。**

标完 `supply` 后，务必验证一次：

1. 把哨兵放到场地任意位置
2. 手动发一个到 supply 坐标的导航目标（RViz 点 2D Nav Goal，或用决策触发残血回家）
3. **确认 Nav2 能规划出路径、哨兵能真的开到那个点**
4. 如果规划失败 / 到不了 → 说明点选在了障碍里或不可达区，换个位置重标

## 六、标完怎么快速自检

坐标填完后，上场前跑一次链路自检，确认没填错格式、profile 能正常加载：

```bash
# 1. 重新编译(profile 是 share 目录, 改完要重装)
cd ~/omni_navigation
colcon build --packages-select omni_decision_sample

# 2. 链路自检
source install/setup.bash
ros2 run omni_decision_sample preflight_check.py --ros-args -p odom_topic:=/odometry
```

再用可视化工具跑一遍行为（详见 `实车测试指南.md`）：
- 按「①满血」看是否去 `opening_strike` 打点位
- 按「②残血」看是否去 `supply` 补给点
- 切前哨站状态看巡逻路线是否在 `patrol` / `patrol_aggressive` 间切换
- 若配了 `bump_segments`：让哨兵去段对侧目标，看是否进 `BUMP_TRAVERSE` 并冲过（先平地假坎，见测试指南 4.5 节）

## 七、常见坑

| 现象 | 原因 | 排查 |
|------|------|------|
| 加载 profile 报错 | YAML 格式错（缺冒号/缩进/花括号） | 检查改动行的格式，对照未改的行 |
| 哨兵往地图原点(0,0)跑 | 某个坐标漏填或字段名拼错 | 确认字段名和缩进和原文件一致 |
| 补给时到不了/一直转 | supply 点不可达 | 按第五节重新验证可达性 |
| 读坐标读到的一直是0 | odom 话题名不对 | `ros2 topic list \| grep -i odom` 找实际话题名 |
| 改完没生效 | 没重新 build（profile 装在 share 目录） | 重新 `colcon build` 再运行 |
| 启动报 "bump segment not X-aligned" | 起伏段 entry.y 与 exit.y 差太大 | 段必须沿 x 轴，重标或放宽 `bump_y_tol`（见 4.5 节） |
| 起伏段冲不过去/一直退回 | `bump_dash_speed` 太低翻不过波浪 | 平地假坎验证后逐步调高穿越起伏段速度 |

## 八、一句话总结

**在两个 profile YAML 里，把带 `# TODO 实车标定` 的坐标（红蓝各一套）换成实车用 `ros2 run tf2_ros tf2_echo map gimbal_yaw` 读到的 **map 系** x/y 值（不要读 /odometry，那是 odom 系）；补给点额外验证 Nav2 可达；起伏段 entry/exit 同法标定且 entry.y≈exit.y；改完重新 build 并跑 preflight_check.py 自检。**
